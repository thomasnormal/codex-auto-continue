# Engineering Log

## 2026-03-18

- Fix: the new `br=...` branch display now prefers the live tmux pane path (`#{pane_current_path}`) over the daemon runtime's stored `cwd`. The first implementation had incorrectly reused the daemon runtime cwd, which was really the directory where the shared daemon had been started. That made branch labels flicker between the repo branch and `-` after daemon restarts or commands launched from different directories. Status now reads the branch from the live pane path and only falls back to the stored cwd when there is no live pane.
- Change: `acw status` now shows the live git branch in the main `WINDOW/PANE` cell as `br=<name>` instead of the mostly internal runtime id. Branch detection is driven from the managed runtime's `cwd` with a short TTL cache so interactive `acw` does not shell out to `git` on every refresh. Detached heads render as `br=@<sha>`, and non-git/unresolved rows fall back to `br=-`. The runtime id is still preserved in `status --details` and `doctor`.
- Change: widened the plain-text fallback `WINDOW/PANE` width cap so short branch labels like `br=main` are not truncated away just because the tmux session/window name is long. The Rich table already had enough vertical space; the subtle issue only showed up in the one-line plain fallback used by non-TTY/local integration runs.
- Change: added a first conservative loop detector in the `acw` daemon. It fingerprints docs-only checkpoint-style turns from the live pane text and auto-pauses a managed session after 4 matching turns on the same markdown file set. The first implementation is intentionally narrow: it targets the low-value pattern of repeated plan/log checkpoint commits without trying to classify every kind of unproductive repetition.
- Change: `acw resume <target>` now treats an explicitly targeted idle managed session as a request to send its saved continue message immediately. Paused sessions still resume via restart to avoid backlog replay, but a healthy `waiting` session now gets a direct daemon-routed continue send, while `busy` and `input` sessions are left alone with explicit operator-facing messages.
- Fix: bare interactive `acw` now exits cleanly on `Ctrl-C` in the PTY path. The interactive watch branch had bypassed the existing top-level `KeyboardInterrupt` handler, so a `Ctrl-C` during terminal-state teardown could leak a traceback from `_CbreakInput.__exit__` instead of just returning to the shell.
- Change: renamed the status-table text columns to `LAST AGENT MESSAGE` and `CONTINUE MESSAGE` so the two long free-text columns are explicit instead of relying on the overloaded `LAST_AGENT` / `MESSAGE` shorthand.
- Change: de-emphasized the `TIME` column in the Rich `acw status` table. The compact `s:` / `l:` labels are now dim, and the whole average-cadence line (`a: ...`) is dim so the age/recency data stays readable without competing with `STATE` and `LAST_AGENT`.
- Fix: the new dead-session adoption path in `acw repair` / `acw restart` no longer deletes the source saved session before the replacement session/runtime has been created successfully. Review of the unstaged recovery changes found that a failed restart could otherwise lose the operator's saved continue message and name. The source session is now removed only after the new session upsert/recreate succeeds, with regressions covering both restart and repair failure paths.
- Change: the interactive bare-`acw` watch view now shows a compact shortcuts header instead of the old static "Watching acw status" banner: `Ctrl-C: exit; e: edit; s: start; p: pause; u: resume; r: restart`. The watch parser now supports the matching `s/start` and `u/resume` aliases directly in the live terminal. Command execution still temporarily restores the terminal and suspends the Rich live renderer so editor-driven flows like `edit` work correctly. Command feedback at the bottom is transient: visible output automatically disappears after 10 seconds, and clean-success `edit` / `pause` / `resume` commands stay silent unless they produce a warning or an error.
- Change: `acw` now detects live Codex approval/trust prompts as a separate `input` activity/state instead of misclassifying them as idle `waiting`. The parser keys off real Codex UI strings such as `Tool call needs your approval`, `Do you trust the contents of this directory?`, the numbered `Yes/No` approval choices, and the approval review help text, while still ignoring those lines as pane chrome for `LAST_AGENT`.
- Change: combined the status table's `STARTED`, `LAST_ACW`, and average-continue cadence into one compact `TIME` cell with three lines: `s: <started>`, `l: <last continue>`, and `a: <average cadence>`. This keeps the timing data together, removes the old `/acw` suffix noise, and frees a full table column for wider agent output.
- Fix: the pane-activity parser no longer flips `busy` sessions to `waiting` just because a stale `working...` line remains above a reappeared prompt. Busy detection now distinguishes soft transient markers like bare `working...` from hard live-work markers like `esc to interrupt`, `Waiting for background terminal`, or queued-message chrome. After a prompt returns, soft markers are treated as stale history, but hard markers still win even if there is intervening ordinary output above the prompt.
- Change: the Rich live bare-`acw` watch header no longer adds its own extra `Sessions: N` line above the table. The live view now keeps only the persistent “Watching acw status…” header and the table itself, while the plain-text fallback remains unchanged.
- Change: the interactive bare-`acw` watch path now uses a real Rich `Live` renderable when `rich` is importable in the running interpreter, instead of trying to capture ANSI-colored status text after the fact. The watch view now reuses the same status-row builder as one-shot `acw status`, renders the live table with actual styled cells, and only falls back to the old plain-text repaint path when `rich` is genuinely unavailable (for example in the temporary-HOME local integration harness).
- Change: bare `acw` is now interactive in a real terminal. With no subcommand and a TTY, it continuously refreshes the status table once per second so live pane state and recent agent output update in place. `acw status` remains the one-shot snapshot command, and bare `acw` still falls back to that static behavior when stdout is not a TTY.
- Change: the interactive bare-`acw` watch loop now renders each frame off-screen and only repaints when the visible status text actually changes. It also switched from full-screen `2J` clears to cursor-home plus clear-to-end-of-screen, which removes most of the visible flash between refreshes.
- Change: `acw status` now adds a compact average continue cadence line in the `LAST_ACW` column, rendered as `<duration>/acw` such as `1h10m/acw`. The value is computed from thread age divided by the durable per-session `continue_count`. For older live sessions that predate the new counter, the status renderer temporarily falls back to counting `continue: sent` lines in the watch log until the daemon persists the counter on the next send/restart.
- Change: healthy managed runtimes no longer all collapse to `running` in `acw status`. If a live pane proves that Codex is idle at a prompt, the state column now shows `waiting`; if the pane shows an active working/background-terminal indicator, it shows `busy`. `running` is now effectively the fallback when `acw` cannot prove a more specific live activity label.
- Change: shortened the paused active-state label in `acw status` from `thinking/working` to `busy` so the state column stays compact while still distinguishing actively working panes from idle `waiting` ones.
- Change: `acw status` now distinguishes paused sessions that are still actively working from paused sessions that are idle and waiting. The status table shows that live pane activity inline for paused rows, and `status --details` prints a dedicated `PAUSED_ACTIVITY:` line. The implementation reads the current bottom-of-pane Codex chrome directly from `capture-pane` instead of guessing from saved watcher state.
- Fix: paused-pane activity detection now gives explicit Codex working indicators precedence over queued `› ...` prompt lines. Real panes can show both at once when input has been queued while Codex is still busy; treating the prompt as authoritative misclassified actively working panes like `avip` as `waiting`.
- Change: the local fake-Codex harness now behaves more like the real Codex CLI for idle/busy pane detection: it renders a visible `›` input prompt while waiting for input, clears that prompt once a message is submitted, emits a short `working...` marker while the request is in flight, then restores the prompt after replying. This makes the local tmux integration suite a much better proxy for pane-state UI work.

## 2026-03-17

- Refactor: replaced `codex-team`'s ad hoc `ready` / `busy` / `launch_requested` / `initial_prompt_sent` / `ignore_next_completion` boolean pile with an explicit `TeamAgentPhase` model (`shell`, `starting`, `ready`, `busy`). The runtime now transitions on phase directly, while saved team JSON still includes the derived boolean fields for compatibility with existing status checks and harness assertions. `load_team_state()` also upgrades legacy boolean-only JSON into the new phase model automatically.
- Fix: hardened the real Codex harness cleanup to terminate background `codex-team` monitor pids explicitly before deleting the temporary HOME tree. The refactor exposed that relying on tmux-server shutdown to race those detached monitor processes to exit was brittle and could leave `.codex/` non-empty during `TemporaryDirectory.cleanup()`.
- Refactor: split `bin/codex_team.py` into explicit `codex_team_state.py`, `codex_team_protocol.py`, and `codex_team_runtime.py` modules, with `codex_team.py` reduced to tmux/CLI wiring plus thin wrappers that preserve the existing unit-test patch surface. This makes the team monitor state machine, prompt/routing protocol, and JSON persistence independent instead of mixing everything in one file.
- Refactor: extracted the shared Codex runtime helpers out of `auto_continue_logwatch.py` into `bin/acw_codex.py`. `codex-team` now imports Codex log parsing, live thread discovery, and tmux send-key injection from the neutral helper module instead of depending on the watcher implementation file. Kept the old `auto_continue_logwatch` patch/test surface with thin wrappers so the refactor stays behavior-preserving while removing the backwards dependency.
- Fix: `acw repair` and plain `acw restart` now recover a live pane from one uniquely matching dead saved session with the same tmux window name. When a stale saved session like `bugs/%5` is dead but a live unmanaged `bugs/%50` pane proves a different live thread, the manager now adopts the dead session's saved continue message onto the live thread, removes the stale thread row, and starts/restarts management on the live pane instead of blocking on “no saved continue message”. Real use also exposed one extra nuance: the dead session could still have a stale runtime row on a missing pane, so the recovery helper now ignores watcher rows whose panes are already gone. Added unit regressions for explicit-target repair planning, no-target repair discovery, and restart adoption/removal behavior.

## 2026-03-16

- Change: `codex-team` now launches worker panes with explicit `model_reasoning_effort="medium"` and `plan_mode_reasoning_effort="medium"` overrides, while the leader keeps the operator's normal Codex config. Added a unit regression for the exact launch command and a real tmux+Codex integration test that proves the worker pane boots with the `medium` banner while the leader keeps the inherited default (`xhigh` on this machine).
- Change: `codex-team` now uses tmux's `main-vertical` layout after team creation instead of `tiled`. The default layout is now the leader pane on the left with the worker panes stacked on the right, which matches the operator model much better than a symmetric grid.
- Change: added `codex-team down` as the explicit teardown command. `stop` now means "stop the monitor and forget the team state, but leave panes/processes alone", while `down` means "stop the monitor, keep the current pane, and close the other panes in that tmux window". This makes teardown predictable because the operator can run `down` from whichever pane they want to preserve.
- Change: `codex-team` now injects queued leader->worker and worker->leader messages immediately once the target Codex session has been launched, even if that pane is currently busy. The monitor no longer waits for the agent to become ready before calling `tmux_send(...)`; it relies on Codex's own in-pane queued-message behavior instead. Added a deterministic local regression that proves a second worker message is drained from `pending_messages` while the worker is still busy, plus a real tmux+Codex integration check that exercises the same busy-worker queue path.
- Fix: `codex-team` now bootstraps the leader asynchronously after the setup command returns. The earlier design tried to wait for leader readiness from inside the same pane that was supposed to become the leader, which deadlocked the leader startup: workers could launch because their panes were idle shells, but the leader pane was still occupied by the `codex-team` process itself. The command now waits only for worker readiness, returns control to the leader pane's shell, and lets the background monitor launch and initialize the leader immediately afterward.
- Fix: `codex-team` no longer depends on a live shared log tailer for routing completions. The team monitor now polls the Codex log for the latest unhandled completion per agent thread using the same thread/turn identity model as `acw`, then marks that completion handled in the per-agent state. This removed the startup tail race and fixed the missing leader -> worker -> leader routing path in both the local fake-Codex harness and the real tmux+Codex integration test.
- Change: added a new `codex-team` CLI. It creates a leader pane plus `n` worker panes inside the current single-pane tmux window, launches Codex in each pane, and starts a background per-window team monitor that routes leader `<message to="agentN">...</message>` tags to the named worker and routes worker replies back to the leader as `<reply from="agentN">...</reply>`.
- Change: added real local-tmux integration coverage for `codex-team` using the fake-Codex backend. The new tests prove the full create-team flow and a real leader -> worker -> leader round trip on a private tmux socket instead of only unit-testing the parser.
- Realization: `auto_continue_logwatch.discover_thread_for_pane()` had a real tmux targeting bug. It was using `list-panes -t %pane -F #{pane_pid}`, which returns every pane in the containing window rather than the exact target pane. The fix was to resolve the pane PID with `display-message -p -t %pane #{pane_pid}` so strict live thread discovery keeps working when a window has multiple panes.
