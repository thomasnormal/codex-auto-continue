The manager now finds the Codex subprocess tree under the pane shell, sends `SIGTERM` to the top-level Codex child to get back to a real shell, waits for the shell prompt, relaunches `codex resume <thread-id>`, and only then restarts the watcher. This fixes the live failure mode where a blind `C-c` merely interrupted the current Codex turn and injected the literal `codex resume ...` text into the still-running session.

Thread discovery now only trusts direct process-owned evidence from the live Codex process: pid->thread rows in Codex's SQLite state, an explicit `codex resume <thread-id>` argv, or thread ids embedded in the process's open Codex session/rollout files. If none of those prove the thread, `start`/`restart`/`edit` fail and `status`/`doctor` report an unresolved pane instead of inventing a best-effort answer.

It claimed panes `%2`, `%3`, and `%4` shared one thread even though they were clearly different Codex agents. With direct process inspection only, those panes resolve to three different threads (`019cbe95…`, `019ce769…`, and `019cb070…`), which is the behavior `acw` needs if the status table is supposed to be trustworthy.

- Change: hardened `status`, `doctor`, `restart`, `edit`, `start`, and dead-session cleanup around that identity model. `status` now shows duplicate/missing entities as invariant errors instead of hiding them behind a merged row, `doctor` reports watcher identity mismatches explicitly, `restart`/`edit` fail rather than guessing when pane and watcher disagree on the thread, `start` rejects duplicate live panes for one thread, and `cleanup` now decides dead-session removal from the shared runtime model instead of an ad hoc pane scan.

- Change: made `acw restart` with no target best-effort across panes. A duplicate-thread or other per-pane restart failure now logs an error for that pane, continues restarting the remaining panes, and prints a short failure count at the end instead of aborting the whole batch on the first `SystemExit`.

When any row is `dead`, the status footer also prints a cleanup hint.
- Change: hardened session identity handling across `start`, `restart`, `status`, and `doctor`. `acw` now rejects starting a second watcher on an already-watched thread, prefers saved session->pane recovery over bare window-name matches for watcher commands, lets `status <target>` match saved session names even without a live pane, and lets `doctor` fall back to the running watcher's recorded thread when pane scraping is stale.
- Change: `acw restart` and `acw resume` now prefer the existing watcher's recorded thread id over fresh pane-based thread discovery. This avoids paused watchers being rebound to whatever Codex thread happens to be visible in the pane at restart time, which could otherwise produce duplicate-thread warnings against unrelated live agents.
- Change: removed the `msg:` prefix from the status-table MESSAGE column. The table now shows the saved continue prompt text directly, which is easier to scan and matches what `acw edit` opens.
- Change: removed `--message-file` support from the CLI and watcher process. `acw` now treats continue prompts as plain message text only: either passed with `--message` or edited interactively, then persisted in the session state for restart/edit/status paths.
- Change: `acw edit` now seeds the editor from the canonical persisted session message for that watcher, instead of trusting the inline `--message` text still visible in the running `auto_continue_logwatch.py` process. This fixes paused/recovered watchers like `ddr3` showing the default workstream placeholder in `edit` even though `status` already showed the correct saved plan message.

- Change: `acw restart <target> --restart-codex` now handles Codex's directory-trust prompt during the in-pane `codex resume <thread-id>` relaunch path, which was required for the real-Codex end-to-end restart flow to complete reliably in a fresh isolated home.
